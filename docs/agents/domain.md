# Domain docs

Use the repository `domain-modeling` skill's layout. Read `CONTEXT-MAP.md` when
present to locate the relevant context. Otherwise, read root `CONTEXT.md` when
present. A skill that refers to `GLOSSARY.md` uses `CONTEXT.md` in this repository.

Read the source documents routed by `AGENTS.md` for the affected area. Read
existing architectural decisions in that area before reopening a decision.
Create context documents and ADRs only when the task resolves a term or durable
decision. If a context document is absent, continue with existing repository
terminology rather than scaffolding an empty glossary.

Keep product terminology separate from implementation plans. Record a resolved
term with the repository skill's context format and a durable decision with its
ADR format. Surface conflicts with an existing decision before changing it.
